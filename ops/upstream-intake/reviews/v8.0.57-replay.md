# v8.0.57 replay review

Candidate: complete upstream tree `v8.0.57` (`c2f402b4`), published
`2026-11-05T16:20:39Z`, replayed onto our `main` at the time of intake.
Baseline for comparison: accepted `v8.0.51` (`7cad1cb7`). Selection followed the
newest-release policy recorded in `ops/upstream-intake/absorbed.md`; no age gate
applies.

## Delta

56 non-merge commits plus 12 merge wrappers between the two releases: 41 fix,
8 feat, 3 refactor, 2 docs, 1 perf, 1 chore. Configuration keys were only added,
never removed; the plugin ABI stays at schema 10; the toolchain stays at
`go 1.26.10`.

Upstream migrated JSON handling to `github.com/MoeForge/moego/ojson` and
`moego/base64` and forbids `tidwall/gjson`, `tidwall/sjson` and the standard
`encoding/base64` in its own rules. The replay migrated every fork-owned Go file
that still imported `tidwall/*` in place, rather than reintroducing the dropped
modules, so the tree carries one JSON implementation.

## Integration points restored after the tree merge

A complete-tree replay replaces shared files wholesale, so fork behaviour that
lived inside them disappears unless it is re-applied deliberately. These points
were re-applied onto upstream's new `ojson.Doc` flow and are each covered by
their existing tests:

- Outbound tool-contract validation (`helps.ValidateOutboundToolContract`) in
  the Claude, OpenAI-compatible, Gemini, Codex, xAI and Meta executors, always
  after payload rules and before the request is built. A later inventory pass
  found three more call sites that the replay had dropped with their upstream
  files and that the remaining tests did not catch: the AI Studio translation
  path, the Antigravity streaming request, and all six Gemini Vertex dispatch
  paths. They were restored, and the new protocol-hook inventory
  (`ops/upstream-intake/check-fork-hooks.py`) now fails a replay that loses a
  recorded integration point inside a file that still exists.
- Codex websocket steering: item-ID repair, replay probe before and after the
  payload finalizer, and the payload finalizer itself.
- Transport attempt observation: `usageTTFTRoundTripper` wraps dispatch in
  `observeHTTPAttempt`, so journal, admission budget and identity contracts keep
  working for model and auxiliary traffic.
- Antigravity catalog probe: the probe registers auxiliary work and instruments
  its client, which upstream moved into `sdk/auth`. `AntigravityModelProbeRequest`
  gained an optional `WrapClient` hook for that; the probe still fails closed
  when admission rejects it.
- Codex multi-agent: the handler consults `CodexMultiAgentV2Enabled()` so the
  historical SDK and Codex settings keep enabling the optimizer.

## Verification

The regression gate `ops/upstream-intake/verify-absorb.sh` passes on the
candidate commit with `GOTOOLCHAIN=go1.26.10`; the log is stored with the
intake evidence. Two gate stages tolerate recorded upstream defects only:
`go vet` for the pluginhost copylocks finding and the full suite for the three
upstream test failures listed in `known-upstream-test-failures.txt`. Both lists
were derived from a pristine `v8.0.57` worktree, and anything outside them still
fails the gate.

One antigravity credits test failed once under full-suite load and passed on
re-run, on its own and later in the same stage; the package's global registries
and the 5s refresh waiter make it load-sensitive. Treat a repeat as a real
signal rather than a known defect.

Retiring F05/F06 removed 37 fork-owned test files covering Gemini, AI Studio,
Antigravity and OpenAI-compatible terminal, usage and buffered-SSE semantics.
Their behaviour is now upstream's, so the tests no longer describe this tree.
Two wall-clock assertions in `executor_payload_optimization_test.go` are skipped
under the race detector because the detector changes absolute timings; the
allocation bounds still run there.
