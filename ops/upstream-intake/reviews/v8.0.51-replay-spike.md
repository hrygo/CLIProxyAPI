# v8.0.51 replay spike

Status: **not accepted**. The candidate starts at upstream release v8.0.51
(`7cad1cb7df48c6c5ffb7ff0b34ef8198806115bc`). Fork changes are recorded as
focused commits on `codex/upstream-v8051-replay`; this branch does not replace
fork `main` or establish a new accepted upstream baseline.

## Verified locally

The first-frame timeout retries and returns 504 after its retry budget. Responses
tools are prepared for the selected route and checked at final outbound boundaries;
Devin checks its actual Connect frame. Home WebSocket tests exercise native and
bridge routes, retries across both routes, session credential identity, and
per-frame authorization against localhost fixtures. Vertex service-account,
Interactions, and AI Studio relay tests exercise both accepted and rejected wire
requests. The Gemini stream accounting buffer merges only fields actually received,
preserving earlier values and honoring explicit zero updates.

The complete gate ran with Go 1.26.10 on 2026-11-05. Maintenance tooling,
gofmt, `go vet`, responses-tools invariants, seven race-sensitive packages,
and server build passed. The full suite failed solely on
`TestReplayAuditPartialUsageTailsRetainLaterFields`. The reproduction is tracked
as a deliberately failing regression test; it blocks acceptance. The raw gate
log is retained in `.git/task-evidence/upstream-v8051-replay-validation-20261105/`.

## Gemini usage boundary

After a finish frame, a first partial `usageMetadata` frame currently triggers
`response.completed`; fields supplied by a later usage frame cannot update that
already-sent event. Waiting for upstream EOF would preserve late fields but can
also leave clients waiting indefinitely when a provider keeps the connection
open after a complete usage frame. The maintainer chose to preserve prompt
completion and defer acceptance of this candidate while the client-facing
counterexample remains unresolved. Internal accounting can retain later fields
only while the request is still alive and those frames are actually received.

The [Gemini API documentation](https://ai.google.dev/api/generate-content)
describes the metadata fields but does not identify a final usage snapshot.
The [Google Gen AI Python SDK](https://github.com/googleapis/python-genai/blob/main/google/genai/_extra_utils.py)
treats streamed usage as an updated running total. Neither field presence nor
the first usage frame is evidence that further updates cannot arrive.

## Remaining limits

- Devin rejects unknown protobuf fields while a tool contract is active, and
  rejects multiple native custom-output history that cannot be restored
  losslessly from the protobuf.
- Home bridge continuation tests resend `tools`; omission is not automatically
  inherited. `response.append`, midstream retry after bootstrap, and a live
  CLIProxyAPIHome deployment were not verified.
- All provider and WebSocket evidence uses isolated local fixtures; no new
  real-client, real-provider, release, deployment, or performance claim follows.
