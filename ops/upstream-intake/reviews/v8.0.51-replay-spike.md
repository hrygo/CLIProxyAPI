# v8.0.51 replay spike

Status: **not accepted**. The candidate starts at upstream release v8.0.51
(`7cad1cb7df48c6c5ffb7ff0b34ef8198806115bc`). Fork changes are recorded as
focused commits on `codex/upstream-v8051-replay`; this branch does not replace
fork `main` or establish a new accepted upstream baseline.

## Origin of the Gemini stream behavior

The fork's `47b61ca0` added a wait after a finish without same-frame usage to
retain usage sent separately. The locally running release at source revision
`415b85360ab9c883efe5598e5b94cf08a7f214b3` contains that behavior. Its
usage-only tail does not itself end the response; the executor also filters
the native Gemini `[DONE]` marker and synthesizes it only at clean EOF.
Consequently, a provider that keeps the connection open can leave the client
waiting. This is a source-level finding, not evidence that a production request
encountered that sequence.

Upstream also contains a related wait in `5ec31442`, present in the v8.0.51
release; the two commits are not ancestors of one another, and their history
does not establish whether one implementation drew on the other. Upstream's
native Gemini marker filtering predates both, and its Responses mapping also
omits `toolUsePromptTokenCount` from client-facing input usage. The internal
usage parser already includes that field, so the omission is specific to the
Responses mapping. Neither behavior was introduced by replaying the fork onto
v8.0.51.

tools are prepared for the selected route and checked at final outbound boundaries;
Devin checks its actual Connect frame. Home WebSocket tests exercise native and
bridge routes, retries across both routes, session credential identity, and
per-frame authorization against localhost fixtures. Additional tests exercise
`response.append`, rejected append before create, two-session isolation,
connection loss before and after output, and explicit recovery without replaying
an uncertain turn. A 429 before output retains the upstream error for Home
credential exclusion; terminal delivery remains tracked through drain without
retaining the released Home concurrency slot. Vertex service-account,
Interactions, and AI Studio relay tests exercise both accepted and rejected wire
requests. The Gemini stream accounting buffer merges only fields actually
received, preserving earlier values and honoring explicit zero updates.
Malformed token counts cannot overwrite trusted values; a client terminal omits
usage when an invalid field has no trusted prior value. Gemini, Vertex API-key
and Vertex service-account fixtures verify that terminal delivery does not wait
for EOF. Token counts accept quoted and exponent forms described by
[ProtoJSON](https://protobuf.dev/programming-guides/json/) without passing
through floating-point conversion.

After the maintainer selected prompt completion, the Responses translator emits
a terminal when Gemini reports a finish. Client-facing input usage includes
both prompt and tool-use prompt tokens observed by that point. The Gemini,
Vertex, AI Studio and Antigravity Responses paths close their output after a
translated terminal, and preserve delivery acknowledgements for usage reporting.
Their local fixtures cover a held upstream connection, multiline and split SSE
events, cancellation, and downstream write errors. Incomplete streamed tool
arguments fail rather than produce a successful tool call. Antigravity replay
continues to follow valid upstream completion, independently of downstream
delivery; malformed or truncated JSON does not establish that completion.

Replay-completeness checks restored the fork's GLM tool-result format, Claude

## Gemini usage boundary

The candidate examines complete SSE events already in the application's read
buffer, or in the current AI Studio relay batch, before delivering a terminal.
An unfinished relay event whose last observed type is an error is also rejected.
Validated usage snapshots contribute to both the terminal and internal
accounting. Antigravity can retain a detached signature-only tail from that same
buffer for a later tool turn; it does not replay unvalidated tail content.
The check performs no additional network read. It rejects errors observed in
that boundary instead of reporting success, and does not expose buffered error
bodies.

The candidate still sends the terminal without waiting for the next network
read. Usage, signatures, grounding and errors that have not reached the
application buffer can be missed, including data still buffered by the OS.
Incomplete events are not treated as complete. The maintainer chose prompt
completion despite these limits and deferred candidate acceptance. The
accounting record's integer fields cannot distinguish unknown counts from zero;
a partial observation can look like a complete lower count and must not be
treated as an authoritative total.

Upstream v8.0.51 also cannot add later usage or signatures to a terminal it has
already sent. When finish arrives without usage, however, its translator waits
for a first usage frame before emitting the terminal; its executor can continue
reading afterward. The candidate's earlier closure can therefore miss even a
first later usage frame or subsequent read error that upstream would have
observed. Neither strategy can guarantee both prompt completion and a complete
result without an upstream finality signal or a different completion contract.

The [Gemini API documentation](https://ai.google.dev/api/generate-content)
describes the metadata fields but does not identify a final usage snapshot.
The [Google Gen AI Python SDK](https://github.com/googleapis/python-genai/blob/main/google/genai/_extra_utils.py)
treats streamed usage as an updated running total. Neither field presence nor
the first usage frame is evidence that further updates cannot arrive.

## Upstream signature format change

The original fork accepted the Antigravity Claude CAQS envelope only for
channel 18. Upstream commit `7517549a`, included in v8.0.51, accepts any present
varint channel because the channel can change across key generations; it
retains the envelope version, infrastructure, block kind, container and strict
encoding checks. The candidate retains that upstream behavior. These checks
validate structure, not cryptographic authenticity or cross-account replay
compatibility. Upstream's channel tests use local fixtures, so they do not prove
that any channel's signature will be accepted by the real service.

## Remaining limits

- Devin rejects unknown protobuf fields while a tool contract is active, and
  rejects multiple native custom-output history that cannot be restored
  losslessly from the protobuf.
- Meta retains the original fork's compatibility conversion independently of
  the multi-agent optimization setting or client user agent. It rewrites
  `agent_message` items and removes `author`, `recipient` and
  `internal_chat_message_metadata_passthrough` from input items, including
  ordinary messages. This Meta-specific behavior is stated in the example
  configuration; it is not evidence that a real Meta service was contacted.
- Home bridge continuation tests cover both resending and omitting `tools`;
  omission is not automatically inherited. A live CLIProxyAPIHome deployment
  was not verified. In native and bridge socket-backpressure fixtures, draining
  or upstream disconnect releases the Home slot and upstream side, but an
  already-blocked downstream write can keep the handler until the client
  closes. The native fixture reproduces this limit on upstream v8.0.51.
  The fixture checks a drainable source, not every possible source goroutine.
- An Antigravity fixture built from the upstream release reproduces a detached
  `thought:true` signature being associated with the preceding function call.
  This upstream behavior is retained; a mismatched signature may affect a later
  tool turn.
- AI Studio retains upstream's handling of a pre-finish SSE `event: error`
  without data: the relay discards that event. For `event: error` combined
  with `data: [DONE]`, isolated fixtures show both upstream and the candidate
  can report completion without an error. Error checks for a finish event and
  its already-buffered tail do not change these paths.
- When an OpenAI-compatible stream completes a named function call without
  arguments, both the original fork and upstream v8.0.51 can report `{}` in
  the item-done event but an empty string in the completed response. This
  comparison covers a `[DONE]` terminator; clean EOF behavior differs.
- In an OpenAI-compatible stream, usage observed before an invalid
  `apply_patch` argument can be recorded as zero when validation fails. The
  pinned upstream has the same failure-reporting order. The original fork did
  not have this validation path, so that exact case cannot be compared to it.
- Direct Codex duplex executor calls without a Manager replay checker retain
  their existing passthrough boundary; they do not obtain a checker implicitly.
  The new WebSocket fixtures use the real checker with a local upstream, but
  do not exercise a complete public handler and Manager route.
- A read-only local process inspection on 2026-11-05 found the running
  CLIProxyAPI instance had not enabled its Home integration, and found no
  separate process named CLIProxyAPIHome. This does not establish whether a
  renamed process or a deployment on another host exists.
- All provider and WebSocket evidence uses isolated local fixtures; no new
  real-client, real-provider, release, deployment, or performance claim follows.
