# v1.5.2-upstream8.0.57 - 2026-11-06

## Summary

- Replays the complete upstream v8.0.57 tree (56 non-merge commits since v8.0.51) onto `main` while keeping the fork's own capabilities: strict Codex tool-argument canonicalization, the responses-tools pipeline with `local-refs: "flatten"`, the opt-in `requests.streaming.bootstrap-timeout`, the outbound tool-contract guard, Home websocket identity and GLM tool-result naming.
- Stops maintaining the fork's Gemini/Vertex/AI Studio/Antigravity streaming repairs and the OpenAI-compatible stream-termination repairs: upstream's implementation now owns those paths, so the fork takes it instead of keeping a second one.
- Supersedes the `v1.5.0-upstream8.0.57` and `v1.5.1-upstream8.0.57` tags: both release builds stopped in the regression gate before publishing anything, because the new fork hook inventory could not resolve the trunk in a tag checkout. No artifact was published under either tag; this release carries the same replay tree plus the gate fix.
- Compatibility: no configuration, credential or storage migration. `config.yaml`, `auths/` and the LaunchAgent keep working; the upgrade replaces the binary only.

## Upstream alignment

- Upstream release: `v8.0.57`
- Previous baseline: `v8.0.51`
- Intake record: [absorbed.md](../../ops/upstream-intake/absorbed.md)
- Ported: 56 non-merge upstream commits and 12 merge wrappers covering 839 files, replayed as the complete release tree and merged through PR #45 at `a5df3da2`. Notable content: the JSON stack moves to `github.com/MoeForge/moego/ojson` and `moego/base64`; plugin host schema version 10; structured usage accounting, Vertex routing and Codex traffic handling refinements; toolchain stays at Go 1.26.10.
- Skipped: upstream-only CI workflows (`docker-image`, `auto-retarget-main-pr-to-dev`, `agents-md-guard`, `pr-path-guard`), `FUNDING.yml`, promotional assets and the network model-catalog refresh script stay out per fork policy; no upstream runtime behavior is excluded.

## Breaking changes

- Streaming behavior on Gemini, Vertex, AI Studio, Antigravity and the OpenAI-compatible endpoints now follows upstream. The fork's own repairs for late data, terminal `incomplete` tool streams and buffered usage in those paths are gone; requests that relied on them may observe upstream's behavior instead. Every other request and response contract, configuration key and credential format keeps its previous meaning.

## Added

- Upstream's structured usage accounting, Vertex per-model routing and Codex traffic handling, taken as released.
- A replacement audit in the intake procedure: at every replay, upstream's implementation replaces an overlapping fork implementation, and each retained fork delta is recorded with the evidence that upstream does not cover it.

## Changed

- The JSON implementation is upstream's `moego/ojson` throughout; the fork no longer carries `tidwall/gjson` or `tidwall/sjson` anywhere in the tree.
- The fork hook inventory runs as a gate stage and compares recorded integration points against the trunk (`main` in a worktree, `origin/main` in a release checkout), so a replay that drops a capability inside a surviving file fails before review.
- Gate and PR checks share `check-vet.sh` and `check-tests.sh`, which tolerate only the upstream defects recorded in the intake directory.

## Fixed

- Antigravity credits recovery no longer erases a credits hint that a refresh just published: the cached exhaustion hint is dropped only after it leaves its freshness window, under a mutex.
- The outbound tool-contract guard is applied on the AI Studio translation path, the Antigravity streaming request and all six Gemini Vertex dispatch paths; the replay had dropped those call sites with their upstream files.
- The bulk build gate no longer hard-codes the baseline: the hook inventory resolves `main`, `origin/main`, or the trunk tip the release workflow leaves in `FETCH_HEAD`, so a tag checkout resolves a baseline instead of failing the release.

## Security

- None. No security-relevant upstream change was skipped, and no credential or configuration format changed.

## Validation

- Regression gate on the replay candidate: maintenance tooling, fork hook inventory, `gofmt`, `go vet`, responses-tools invariants, the full test suite, seven race-enabled packages and a server build all passed, including a second run with an empty module cache.
- PR #45 `build` check passed on the same tree; the merged commit keeps the candidate tree byte for byte and both upstream and fork ancestry.
- Coverage limits: the fork's own Gemini-family and OpenAI-compatible stream repairs are no longer tested here because the implementations are gone; upstream's defects and their recorded test failures were reproduced on a pristine v8.0.57 worktree and left unchanged.

## Known issues

- Upstream v8.0.57 ships one `go vet` finding in a pluginhost test and three failing tests; both are recorded in the intake directory and intentionally not fixed, so the gate tolerates exactly those.
- The Antigravity credits recovery ordering is covered by unit tests with a simulated provider; no live Antigravity quota recovery was exercised in this release.
